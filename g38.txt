# Design & Architecture Specification: The Unbounded Action Engine

This specification establishes the blueprint for an action-first, deeply reactive open-world RPG powered by an autonomous, self-optimizing multi-agent development repository.

---

## 1. Game Design Specification

### 1.1 Character Customization & World Reactivity

Player identity is not cosmetic; it is a multi-dimensional state vector that reshapes every interaction in the world.

* **Composite Trait Vector:** Characters are defined by **Background** (e.g., Exiled Scribe, Pit Fighter, Smuggler), **Physical Attributes** (Strength, Agility, Endurance), **Social Markers** (Renown, Notoriety, Faction Markings, Attire), and **Innate Traits** (e.g., Pyromaniac, Tongue-Tied, Night-Eyed).
* **Dynamic Perception & Salience:** What the character perceives depends on who they are. A rogue notices loose floorboards and key rings; a scholar notices script alterations and chemical residues; a brute notices structural fracture points and improvised bludgeons.
* **Granular NPC Reaction Matrices:** Inhabitants check character traits, factions, and past deeds before rendering dialogue or actions. An outlaw NPC will greet a high-notoriety character with wary respect, fleece an aristocrat, or attack a city watchman on sight.
* **Tag-Based Content Interlocking:** Every quest, dialogue branch, and environment interaction queries tags. There are no generic "Adventurer" responses; options reflect the character's explicit abilities and history.

---

### 1.2 High-Velocity Action Prose (Tone & Interface)

The game prioritizes momentum, clarity, and instant comprehension over literary exposition.

* **The Hemingway Baseline:** Descriptions are strictly capped at 1–3 short, active-voice sentences per node.
* **Zero Ornamental Flourish:** Replace atmospheric purple prose with concrete, punchy sensory facts.
* *Disallowed:* "The dimly lit tavern exudes an aura of ancient malice as shadows dance across the worn oak tables."
* *Mandatory:* "Smoke fills the low-ceilinged room. Three armed mercenaries watch the door from a corner table."


* **Dialogue in Plain Speech:** Characters speak directly, using authentic, vernacular cadences without archaic filler or exposition dumps.
* **Action-First UI:** Options are rendered as explicit, telegraphic verb phrases displaying risk, tools required, and mechanical stakes (e.g., `[Kick the brazier into the hay]` or `[Flash guild signet to the lookout]`).

---

### 1.3 World Topology: Skyrim Scale with BG3 Density

The game takes place on a single, continuous world graph balancing continental geography with dense systemic interaction.

```
+-------------------------------------------------------------------------+
|                              WORLD GRAPH                                |
|                                                                         |
|  [Province: The Reach] <====== Highway ======> [Province: The Lowlands] |
|        |                                              |                 |
|    Local Hub                                      Local Hub             |
|  (Town / Fort)                                  (Port / Citadel)        |
|        |                                              |                 |
|  +-----+-----+                                  +-----+-----+           |
|  |     |     |                                  |     |     |           |
| POI   POI   POI (Micro-dungeon / Ruins / Camps: 10-30 interlocking nodes)|
+-------------------------------------------------------------------------+

```

* **Hierarchical State Architecture:** The macro-world is partitioned into Provinces, Hubs, and Points of Interest (POIs). Macro-travel handles distance, weather, and encounters, while local areas unlock interconnected scene nodes.
* **Vertical & Spatial Systemics:** Each POI contains multiple systemic entry points, vertical pathways, hidden bypasses, and alternate faction angles.
* **Persistent World Memory:** Actions taken in one corner of the world ripple outward. Poisoning a reservoir in an upstream POI alters disease rates, faction behaviors, and dialogue states across the entire downstream valley.

---

### 1.4 Unbounded Scene Possibility Space

Scenes are not fixed lists of three choices; they are dynamic affordance queries evaluated against the game's systemic rules.

* **Dynamic Choice Synthesis:** Available actions in any scene are computed at runtime:

$$\text{Choices} = \text{Base Actions} \cup \text{Inventory Affordances} \cup \text{Trait Exploits} \cup \text{Environmental Systemics}$$


* **Systemic Interactivity:** If an asset exists in a scene (e.g., a locked iron grate, an oil lamp, a timber beam), every systemic verb compatible with that object is legal:
* Force with raw strength / crowbar.
* Pick with lockpicks / improvised wire.
* Melt with acid / intense flame.
* Collapse ceiling to crush it.
* Bribe or deceive an NPC on the other side.


* **No Artificial Branch Caps:** A single room can present 10+ distinct actions if the player's tools, stats, and surroundings support them. Every action must carry deterministic consequences.

## 2. Repository Orchestrator Specification

The repository is governed autonomously by an **Orchestrator Agent** serving as the technical director, product manager, and lead architect.

```
+------------------------------------------------------------------+
|                        ORCHESTRATOR AGENT                        |
|  - Strategy & Architecture        - Quality & Performance Audit  |
|  - Workflow & Pipeline Mutation   - Task Scheduling & Delegation |
+---------------------------------+--------------------------------+
                                  |
         +------------------------+------------------------+
         |                        |                        |
         v                        v                        v
+------------------+    +--------------------+    +------------------+
|  Authoring Agent |    |  Verification Bot  |    | Playtester Fleet |
| Content & Quests |    | Graph & Solvability|    | Multi-Persona QA |
+------------------+    +--------------------+    +------------------+
         |                        |                        |
         +------------------------+------------------------+
                                  |
                                  v
+------------------------------------------------------------------+
|                   Triaged Issue & Task Queue                     |
|                   [Self-Healing Patch Loop]                      |
+------------------------------------------------------------------+

```

### 2.1 Orchestrator Scope & Authority

* **Full Process Ownership:** The Orchestrator manages development velocity, evaluates engine quality, audits test results, and determines build milestones.


* **System Self-Mutation:** The Orchestrator has full authority to rewrite repo tooling, refactor directory layouts, overhaul schemas, swap database/queue backends, or alter sub-agent prompts whenever a workflow bottleneck or bug arises.


* **Zero Direct Manual Hand-Holding:** The manager does not wait for user input on technical decisions; it detects friction, devises solutions, tests them in isolated branches, and applies them.



---

### 2.2 Sub-Agent Delegation Hierarchy

| Agent Role | Mandate | Inputs / Outputs |
| --- | --- | --- |
| **Content Author** | Drafts world zones, quests, NPCs, items, and dialogue DAGs strictly adhering to high-velocity prose rules.

 | Schema definitions, character trait matrices $\to$ Declarative World Content.

 |
| **Graph Verifier** | Runs automated BFS/DFS crawlers to mathematically prove reachability, discover softlocks, and ensure all traits have paths to success.

 | World Content $\to$ Winnability Proofs, dead-end traces.

 |
| **QA Playtester Fleet** | Spawns LLM agents with divergent player personas (e.g., speedrunner, brute, saboteur, curious explorer) to play sessions via MCP.

 | Seeded Runs $\to$ Machine-readable session logs, friction reports.

 |
| **Fixer / Remediation** | Takes failing traces and bug tickets, modifies schemas or engine logic, and verifies the fix against the regression suite.

 | Bug Trace $\to$ Deterministic Patch & Unit Test.

 |

---

### 2.3 The Self-Healing Pipeline

1. **Generation:** Author agents craft and connect new narrative sectors.


2. **Headless Verification:** Graph solvers audit the sector for deadlocks, missing references, or unreachable goals. Content failing this step is rejected before simulation.


3. **Fleet Playtesting:** Autonomous personas run randomized seeds through the MCP interface, testing balance, pacing, and tone.


4. **Automated Triage:** Stalls, prompt hallucinations, or schema violations are minimized into reproducible, seeded action vectors and pushed to the issue queue.


5. **Autonomous Patching:** Fixer agents patch the issue, execute the trace to confirm resolution, and merge changes.



---

## 3. Success Metrics & Constraint Verification

The Orchestrator agent evaluates repository success against four hard criteria:

* **Determinism & Replay Fidelity:** 100% of recorded action traces must recreate identical state hashes on replay across seeds.


* **Action Density Ratio:** Every scene node must support a minimum ratio of $\ge 3$ distinct mechanical actions per 50 words of narrative text. Prose-heavy nodes failing this density check are flagged for reduction.
* **Graph Solvability:** 100% of declared quests and zones must be verified winnable by headless graph crawlers under at least three distinct character trait combinations.


* **Autonomous Mean Time to Fix (MTTF):** Uncovered gameplay deadlocks or broken references must be detected, triaged into a minimal reproduction trace, and patched by the agent pipeline without human commits.
